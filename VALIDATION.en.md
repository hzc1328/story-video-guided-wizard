The original release's independent reviews also identified and fixed a ZIP containing a prompt path instead of its contents, full TTS accepting unapproved settings/text, inflexible audio/frame rounding, companion-file overwrites, and false image files. Their regression tests remain included. Full mixing uses auditioned sources/settings, and editing checks complete approved shot order. Mixing now also verifies that the music is the step-10 approved version, and caption type is sized from the frame's short edge and wrapped by measured width so portrait frames pass the safe-area check.

This batch also replaced ad-hoc step constants with one step table and an explicit transition table, rejects reopening unstarted steps, validates storyboard/edit-plan JSON during prepare, caches confirmed-file stat data with a `validate --strict` override, streams video-pack images into the ZIP, burns measured captions as one libass pass with a PNG fallback, and asserts final stream/duration/resolution/fps. Because this machine has no ffmpeg, the single-pass ASS path and final QC assertions were not run locally; the CI ffmpeg integration job covers both Chinese and English synthetic flows.

The third batch was structural: `media.py` is now a thin entry over the `mediakit` package (core/captions/audio/video/audit/providers) with the old patch points intact; Kimi and Doubao calls sit behind injectable-transport adapters, with Kimi restricted to official endpoints; paid and media actions append to `AUDIT_LOG.jsonl` recording only models, hashes, sizes and output names; state files moved to `schema_version` 2 with v1 orders migrated on load, and prepare/approve/reopen/language mutations run under an exclusive `.state.lock` with 60-second stale reclaim; init/summary/validate/prepare/approve/reopen accept `--json` for machine-readable output; the intake card debounces rendering by 120 ms while saving drafts synchronously, and its radio groups, live progress and story-card region gained ARIA semantics; the step tables are kept in line with the code by `scripts/gendocs.py --check/--write`; tag-based release packaging and a Pages deploy workflow were added. Browser assertions (copy after debounce, Chinese-free aria-labels) were covered by the CI Playwright job and not run on this machine at that time; the fourth batch ran them locally and they pass.

The fourth batch generalized themes and naming: the intake card is now parameterized across 12 themes (wedding, proposal, anniversary, birthday, first birthday, graduation, growing up, travel, pet, family, career and brand/product), and a theme must be chosen before its five-act questions render; the `?theme=` parameter and the local draft use the new `story-intake-v2` key. The skill and package were renamed `story-video-guided-wizard`, with README/SKILL/references and the Pages URL generalized to match. Steps 3 and 14 now use the role display name `owner`; v1 `couple` records are normalized through an alias so existing orders keep working, and the CLI accepts both names. Internal identifiers (`WEDDING_FONT`, the mix-settings kind, the Doubao uid, the `wedding_wizard` spec name) are retained for compatibility. Browser assertions were run on this machine with Playwright and Chromium: the question area stays hidden until a theme is chosen, all 12 themes are present, `?theme=` renders the matching theme, the second style question appears immediately after choosing a style, switching language preserves typed answers, no untranslated Chinese remains in the English interface or copied card, clearing does not bring back the old theme after reload, the clipboard fallback works and filling still works without localStorage. The 45 local unit tests and ruff pass. That run also fixed four issues: the second style question waited for the debounced render, the `?theme=` parameter survived a clear, the theme name was not translated in the English copied card, and two photo strings were missing English entries.

## What this does not prove

No paid Kimi, Doubao, music or video generation was run for this update. Synthetic tones and color frames validate code and packaging, not English accent quality, emotional delivery, real faces, narrative quality or the story owner's satisfaction. No real customer story or credentials were used.

Phone checks use browser viewport simulation; clipboard writes are controlled in tests and the actual DOM fallback is exercised. Physical devices and messaging-app browsers such as WeChat were not individually tested. The editing deliverable is a reproducible JSON timeline, not a native Premiere/CapCut project. Provider availability and language support must be checked for the actual account during use.
